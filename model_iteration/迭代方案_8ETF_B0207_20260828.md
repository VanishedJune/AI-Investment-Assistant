## 4. 单支 ETF 标准迭代循环（Worker 流程）

每支 ETF 由独立 Worker 按以下流程执行；命令均为项目既有 CLI。

### S0 启动校验

```powershell
python -m rolling.cli replay --etf <code>   # 仅用于探路，若报 DATA_ASSEMBLY_FAILED 即停
```

要求：`load_aligned_data` 通过、CA 覆盖通过、`state.json` 为干净初始态（`latest_anchor_index=-1`）。

### S1 生成全部盲化诊断

```powershell
python -m rolling.cli diagnose-all --etf <code>
```

输出：`weekly_rolling/diagnostics/ROUND_*.json`（数量 = 该支提案轮次）。

### S2 同步隔离工作区

```powershell
Copy-Item etf_<code>\weekly_rolling\diagnostics\*.json etf_<code>\sanitized_workspace\diagnostics\  # 覆盖
python scripts/export_syntax.py --etf <code>   # spec_syntax.json 缺失时执行
```

### S3 工厂生成草稿（sanitized_only，可晋级）

```powershell
python scripts/sanitized_factory.py --etf <code>
```

输出：`etf_<code>/sanitized_workspace/outputs/ROUND_*.draft.json`；含禁止字段自检，拒绝写出即报错。

### S4 冻结全部 FINAL 提案

单进程循环调用 `freeze_final_proposal(draft, etf)`（数据只装配一次，等价于逐条 `rolling.cli proposal`）：

```powershell
python -m rolling.cli proposal --file etf_<code>\sanitized_workspace\outputs\ROUND_XXX.draft.json --etf <code>
```

输出：`weekly_rolling/proposals/ROUND_*.json`（status=FINAL）。冻结数量必须等于 S1 诊断数量；任何一条校验失败必须修复后重冻。

### S5 回放（首跑 + 续跑）

```powershell
python -m rolling.cli replay --etf <code>
python -m rolling.cli replay --etf <code> --resume   # 每次暂停处理完后续跑
```

退出码协议：

| 退出码 | 含义 | Worker 动作 |
| --- | --- | --- |
| 0 | 回放完成 | 进入 S7 |
| 2 | 数据装配失败 | 停止并上报（前置条件问题，不重试） |
| 3 | AGENT_REVIEW_REQUIRED：缺提案 / 诊断不匹配 / 未冻结 | 补 S3–S4 后 `--resume` |
| 4 | AI_REVIEW_REQUIRED：晋级候选待复核 | 进入 S6 后 `--resume` |

### S6 AI 复核（晋级）

```powershell
python -m rolling.cli approve --candidate <id> --anchor <idx> --decision APPROVE --etf <code>
python -m rolling.cli approve --candidate <id> --anchor <idx> --decision REJECT --etf <code>
```

决策口径：机器硬门禁通过且为推荐候选 → APPROVE（留痕理由）；未推荐 → REJECT；指标异常/冲突 → HOLD 并上报。不自动代替复核。

### S7 完成校验（每支 5 项硬标准，全部满足才算 done）

1. 末次 `replay` 退出码 0 且输出包含 `replay completed`；
2. `state.pending_ai_reviews` 为空；
3. `state.latest_anchor_index == 可用锚点数 - 1` 且 `resume_from == 可用锚点数`；
4. 冻结提案数 == 预期轮次；`events.jsonl` 含 forecast / evaluation / proposal_orchestrated / promotion_checkpoint 且非空；
5. 交付物齐全：`iterations/ITERATION_001_<code>.json/.md`、诊断包、隔离草稿、运行日志。

### S8 写迭代记录

`iterations/ITERATION_001_<code>.json/.md`：记录覆盖区间、初始/最终 Champion、晋级链、提案/挑战者/事件计数、执行规则版本（B0207 v3.0.0）、AI 复核决策摘要；**不写哈希字段**。

- **批门禁**：批内 4/4 通过 S7 完成校验后，才允许启动下一批；
- 批次内某支失败：同批重试 ≤2 次；仍失败 → 批次暂停、上报用户，**不跳过、不提前进入下一批**；
- 全部 8 支 done 后进入总验收。

## 6. 防漏跑与续跑保障（核心）

### 6.1 单一事实来源

`model_iteration/迭代状态_8ETF_20260828.json`，每次事件后原子更新；字段：

```json
{
  "schema_version": "1.0.0",
  "started_at": "...",
  "batch_a": {"159915": {"status": "running", "round": "ROUND_042_prediction", "frozen": 42, "started_at": "...", "finished_at": null, "errors": []}, "...": {}},
  "batch_b": {},
  "gates": {"batch_a_done": false, "batch_b_done": false, "all_done": false}
}
```

状态机：`pending → running → paused_round(轮次) → done`；失败置 `failed` 并记录原因。

### 6.2 完成门禁

- 批门禁：`batch_X_done` 仅当该批 4/4 为 `done` 且通过 S7；
- 总门禁：`all_done` 仅当 8/8 `done`；
- 启动批次前，以 `config/instruments.json` 的 8 码清单 + `configs/etf_<code>.json` 文件存在性交叉核对，防清单漂移。

### 6.3 断点续跑

- 引擎状态 `state.json` 自带 `resume_from` / `paused_at` / `paused_stage`；任何中断直接 `replay --resume` 续跑，天然幂等（不重复成熟/预测/追加事件）；
- Worker 循环每完成一轮（提案冻结或复核）即落盘状态与批次状态文件；
- 阶段超时视为“暂停”而非“完成”，登记后恢复，不重头、不跳过。

### 6.4 日志与监控

- 每支：`etf_<code>/run_20260828.log`（命令、时间戳、退出码、暂停原因）；
- 协调：`model_iteration/logs/迭代协调_20260828.md`（每批启动/完成/异常摘要）；
- 每批结束向用户汇报 4/4 明细后再进入下一批。
